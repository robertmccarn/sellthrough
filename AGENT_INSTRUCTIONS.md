## User Story Format

When creating user stories, use:

As a [persona], I want [capability], so that [benefit].

Every story should include:

- Context
- Acceptance Criteria
- Technical Notes
- Definition of Done

## Rules

- Do not delete issues unless explicitly asked.
- Do not close issues unless the user explicitly says the work is complete.
- Prefer creating GitHub Issues over draft project items.
- Use GitHub CLI commands when possible.
- When creating issues, add them to the GitHub Project if possible.
- Prefer small, practical stories over large vague tasks.
- If project status movement is too complex, create or update the issue and let the user move the card manually.
